# Телеграм-бот онлайн-записи

[![tests](https://github.com/acoupy/tg-booking-bot/actions/workflows/tests.yml/badge.svg)](https://github.com/acoupy/tg-booking-bot/actions/workflows/tests.yml)

**Попробовать вживую: [@rubka_booking_bot](https://t.me/rubka_booking_bot)** — бот
работает круглосуточно, записаться можно прямо сейчас.

Бот берёт на себя запись клиентов: человек за минуту выбирает услугу, специалиста, день
и время, подтверждает и получает напоминание утром в день визита. Владелец видит новые
записи и отмены сразу в Telegram и смотрит расписание дня одной командой.

Код не привязан к предметной области: он умеет «услуга занимает N минут у такого-то
специалиста в такие-то часы». Услуги, специалисты, график и правила лежат в одном файле
[`bot/config.json`](bot/config.json) — салон, автосервис, репетитор, юрист, медцентр
настраиваются правкой конфига, без изменений в коде.

Конфигурация в репозитории — **демонстрационная и намеренно обезличенная**: услуги
названы по длительности, специалисты пронумерованы, адрес и телефон пустые. Это не
заглушки-«рыба», а рабочий минимум: всё, чего нет в конфиге, не появляется и в
сообщениях бота.

## Что умеет

**Клиент**

- запись за 5 нажатий: услуга → специалист → дата → время → подтверждение;
- «любой специалист» — показывает объединённое свободное время всех, кто делает эту
  услугу, и назначает конкретного человека при подтверждении;
- свободное время считается по-настоящему: учитываются смена специалиста, длительность
  услуги, уже занятые часы и запрет записи «через пять минут»;
- телефон берётся кнопкой из Telegram, повторно не спрашивается;
- «Мои записи» с отменой и переносом: перенос выбирает новое время у того же
  специалиста, своё же время при этом показывается свободным, а старое возвращается
  в расписание только после того, как новое удалось занять;
- напоминание утром в день визита;
- экран «Как это работает» — правила записи и контакты, если они заданы.

**Владелец**

- уведомление о каждой новой записи, отмене и переносе: время, услуга, специалист,
  имя, телефон;
- `/today` — расписание на сегодня с итоговой выручкой;
- `/week` — то же на неделю вперёд;
- `/id` — узнать свой Telegram ID для настройки.

## Что настраивается конфигом

| Поле | Что делает |
| --- | --- |
| `title` | название: идёт в имя бота, описание и приветствие |
| `about` | абзац на экране «Как это работает» |
| `address`, `phone`, `site` | контакты; пустые не показываются нигде |
| `services` | список услуг: `title`, `duration` в минутах, `price` (0 — цену не показываем) |
| `specialists` | кто какие услуги делает и в какие часы работает по дням недели |
| `booking_depth_days` | на сколько дней вперёд открыта запись |
| `slot_step_minutes` | шаг сетки расписания |
| `min_lead_minutes` | за сколько минут до начала запись закрывается |
| `max_active_bookings` | сколько записей один клиент держит одновременно |

## Как устроено

Бот живёт на бесплатном serverless-вебхуке: Telegram присылает апдейт, функция
просыпается, отвечает и засыпает. Постоянного процесса нет, поэтому:

- **состояние диалога — в кнопках.** Услуга, специалист, дата и время закодированы в
  callback-данных, поэтому боту не нужно помнить, на каком шаге клиент;
- **данные — во внешнем хранилище.** Redis (Upstash) по HTTP на проде, JSON-файл при
  локальном запуске. Интерфейс один — `bot/storage.py`;
- **двойной записи на одно время не будет.** Каждая клетка расписания занимается
  атомарно (`SET NX`): если два человека жмут одно время одновременно, второй получит
  «время только что заняли», а не запись поверх чужой;
- **повторный апдейт не обрабатывается дважды.** Не дождавшись ответа за минуту (а на
  холодном старте это бывает), Telegram присылает то же самое ещё раз. Номер апдейта
  занимается через `SET NX`, поэтому повтор не отвечает невпопад и не пишет вторую бронь;
- **хранилище не растёт бесконечно.** Каждому ключу при создании ставится срок жизни —
  день визита плюс 30 дней хранения, — а утренний cron досносит остатки прошедших дней;
- **записи старого формата не роняют бота.** Набор полей со временем меняется, а в
  хранилище остаются прежние записи: такая читается как «пропавшая», и индекс
  подчищается сам;
- **сбой не оставляет человека без ответа.** Хостинг о неудачном апдейте узнать не
  может — Telegram всегда получает 200, — поэтому любое исключение перехватывается
  глобально: клиент видит понятное сообщение, владелец — что сломалось и на каком шаге.

| Файл | Отвечает за |
| --- | --- |
| `bot/config.json` | услуги, специалисты, график, правила — единственное, что правится под клиента |
| `bot/config.py` | разбор и проверка конфига |
| `bot/schedule.py` | календарная арифметика: какие начала услуги влезают в смену |
| `bot/booking.py` | брони, отмены, занятость, индексы по клиенту и по дню |
| `bot/storage.py` | Redis по HTTP и JSON-файл за одним интерфейсом |
| `bot/handlers.py` | сам диалог |
| `bot/keyboards.py`, `bot/texts.py` | кнопки и тексты |
| `bot/profile.py` | витрина бота в Telegram: имя, описание, команды, кнопка меню |
| `app.py` | точка входа на Vercel: вебхук и утренний прогон |

## Локальный запуск

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env        # вписать BOT_TOKEN от @BotFather
python run_polling.py
```

В этом режиме хостинг не нужен: бот сам опрашивает Telegram, записи складываются в
`data/bookings.json`.

## Деплой на Vercel

1. Залить репозиторий на GitHub и импортировать проект в Vercel.
2. Storage → создать базу Upstash Redis и подключить к проекту (переменные
   `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` подставятся сами).
3. Добавить переменные `BOT_TOKEN`, `ADMIN_IDS`, `WEBHOOK_SECRET`.
4. После деплоя открыть в браузере `https://ваш-проект.vercel.app/api/setup?key=<WEBHOOK_SECRET>`
   — бот сам пропишет свой адрес в Telegram и заполнит имя, описание, команды и кнопку меню.

Утренний прогон включён в `vercel.json`: `/api/cron` дёргается ежедневно в 06:00 UTC
(09:00 по Москве) — рассылает напоминания на сегодня и убирает дни, вышедшие за срок
хранения. Вернуть бота на локальный режим — `python set_webhook.py --off`.

Через Bot API не задаются только две вещи: аватар и @username бота — это руками
у @BotFather.

## Тесты

```
.venv\Scripts\pip install -r requirements-dev.txt
python -m pytest
```

На каждый push и pull request те же тесты прогоняются в GitHub Actions на Python 3.12
и 3.14 — [`.github/workflows/tests.yml`](.github/workflows/tests.yml).

65 тестов: расписание (услуга не вылезает за смену, выходные, запрет записи впритык),
брони (пересечения по длительности, повторная бронь того же времени, отмена
освобождает время, уборка прошедших дней, сроки жизни ключей, запись старого формата),
перенос (старое время возвращается в расписание, сдвиг внахлёст с самим собой, перенос
на занятое время ничего не меняет, переезд индексов на другой день), тексты (конфиг без
контактов и без цен не оставляет пустых строк), сквозной прогон диалога на подменённой
сессии Telegram — от `/start` до отмены и переноса записи и до упора в лимит активных
записей, прод-хранилище против игрушечного Redis-REST сервера, витрина бота, поведение
при сбое (упавший хендлер отвечает клиенту и уведомляет владельца) и точка входа (чужой
запрос без секрета не проходит, битое тело не роняет функцию, повторный апдейт не
обрабатывается дважды).
